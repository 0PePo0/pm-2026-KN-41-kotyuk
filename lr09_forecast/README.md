## 1. Звідки взялася velocity

| Поле | Значення |
| --- | --- |
| Спринтів у `velocity.csv` | 2 змодельовані спринти; фактичної історії поки немає |
| Тривалість спринта | Два тижні, понеділок пятниця другого тижня; 14 днів між завершеннями |
| Ємність спринта з мого варіанта | 20 SP, за розділом 4 ЛР6 |
| Середня фактична velocity | Не встановлена; середня в моделі (11 + 16) / 2 = 13,5 SP |
| Найгірший і найкращий спринт | У моделі 11 і 16 SP |

Звідки бралися points закритих історій: усі числа взято з поточних
`final_estimate` у `lr08_poker/estimates.csv` після конверта ЛР8;
історій без оцінки або з іншого релізу у моделі немає.

| Спринт моделі | Початок — кінець | Узято історії | Умовно завершено за DoD | Узято / завершено SP |
| :-: | --- | --- | --- | :-: |
| 1 | 2026-11-02 — 2026-11-13 | S-11, S-01, S-02, S-03 | S-11, S-01, S-02 | 19 / 11 |
| 2 | 2026-11-16 — 2026-11-27 | S-03, S-04, S-06, S-14, S-05 | S-03, S-04, S-06 | 24 / 16 |

Ручна звірка спринта 1: узято 3 + 3 + 5 + 8 = 19 SP,
завершено 3 + 3 + 5 = 11 SP. Для спринта 2: узято
8 + 5 + 3 + 5 + 3 = 24 SP, завершено 8 + 5 + 3 = 16 SP.
S-03 переходить із першого спринта в другий і входить до committed обох,
але до done та загального виконаного обсягу тільки один раз.
Незавершені S-14 і S-05 не отримують часткових points.

Чому факт розійшовся з ємністю варіанта: фактичне відхилення ще не відоме;
у моделі середня нижча за орієнтир на 6,5 SP, тобто на 32,5%, що менше третини.
Припущена причина недовиконання моделі S-03 потребує додаткової перевірки
конкурентних змін голосу, а S-14/S-05 не проходять усіх перевірок до кінця
другого спринта. Це умови сценарію, а не встановлені блокери з журналу.
У Monte Carlo використано тільки [11, 16], а не орієнтир 20 SP.

## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | Python 3, код нижче; окремий файл скрипта не створювався |
| Прогонів | 10 000 на кожен із п'яти сценаріїв; усього 50 000 |
| Що тягнеться випадково | Одне значення points_done з поверненням і рівною ймовірністю; для моделі [11, 16] |
| Дата, від якої відлічуються спринти прогнозу | Весь реліз: кінець спринта 1, 2026-11-13, плюс (P - 1) × 14 днів; залишок: кінець спринта 2, 2026-11-27, плюс P × 14 днів |

Один прогін віднімає випадково вибрані завершені SP від обсягу до його
вичерпання; число кроків є кількістю спринтів. P50 і P85 - елементи
відсортованої вибірки на позиціях ceil(0,50 × N) і ceil(0,85 × N),
нумерація позицій від одиниці; результат уже цілий.
Для кожного сценарію генератор запускається заново з seed = 20261028.
Нульова velocity у частині історії дозволена; історія тільки з нулів
для ненульового обсягу відхиляється, щоб цикл не був нескінченним.

Код запускається з кореня репозиторію без сторонніх бібліотек. Шлях REFERENCE
вказує на наданий файл у Downloads; для повторення на іншому комп'ютері
потрібно змінити тільки цей шлях. Параметри model нижче є явними
навчальними припущеннями з таблиці розділу 1.

```python
import csv
import random
from datetime import date, timedelta
from math import ceil
from pathlib import Path

RUNS = 10000
SEED = 20261028
REFERENCE = Path("d:/Downloads/lr09_reference_velocity.csv")

def read_csv(path):
    with open(path, encoding="utf-8-sig", newline="") as stream:
        return list(csv.DictReader(stream))

def monte_carlo(points, history, seed=SEED, runs=RUNS):
    if points < 0 or runs < 1000 or not history:
        raise ValueError("Invalid volume, history or number of runs")
    if any(value < 0 for value in history) or (points > 0 and max(history) == 0):
        raise ValueError("Positive throughput is required for a nonzero scope")
    rng = random.Random(seed)
    outcomes = []
    for _ in range(runs):
        remaining, sprints = points, 0
        while remaining > 0:
            remaining -= rng.choice(history)
            sprints += 1
        outcomes.append(sprints)
    outcomes.sort()
    return tuple(outcomes[ceil(runs * q) - 1] for q in (0.50, 0.85))

backlog = read_csv("lr06_backlog/backlog.csv")
estimates = {row["story_id"]: int(row["final_estimate"])
             for row in read_csv("lr08_poker/estimates.csv")}
release = {row["story_id"] for row in backlog if row["release"] == "REL-1"}
total = sum(estimates[story] for story in release)

# Explicit teaching assumptions; these are not recorded completed sprints.
model = [
    (1, "2026-11-02", "2026-11-13",
     ["S-11", "S-01", "S-02", "S-03"], ["S-11", "S-01", "S-02"]),
    (2, "2026-11-16", "2026-11-27",
     ["S-03", "S-04", "S-06", "S-14", "S-05"], ["S-03", "S-04", "S-06"]),
]
velocity = []
closed = set()
for sprint, start, end, committed, done in model:
    assert set(done) <= set(committed) <= release
    assert not (closed & set(done))
    closed.update(done)
    velocity.append([sprint, start, end,
                     sum(estimates[story] for story in committed),
                     sum(estimates[story] for story in done)])
remaining = sum(estimates[story] for story in release - closed)
history = [row[4] for row in velocity]
full = monte_carlo(total, history)
left = monte_carlo(remaining, history)

def forecast_row(name, points, quantiles, end, offset):
    p50, p85 = quantiles
    def finish(p):
        return (date.fromisoformat(end) + timedelta(days=14 * (p - offset))).isoformat()
    return [name, points, RUNS, p50, p85, finish(p50), finish(p85)]

forecast = [
    forecast_row("Весь перший реліз", total, full, velocity[0][2], 1),
    forecast_row("Залишок після двох спринтів", remaining, left, velocity[-1][2], 0),
]
reference = [int(row["points_done"]) for row in read_csv(REFERENCE)]
training = [
    ("all_12", reference, monte_carlo(220, reference)),
    ("sprints_1_2", reference[:2], monte_carlo(220, reference[:2])),
    ("sprints_5_6", reference[4:6], monte_carlo(220, reference[4:6])),
]

for row in velocity:
    print("velocity:", row)
for row in forecast:
    print("forecast:", row)
for name, values, quantiles in training:
    print("training:", name, values, quantiles)
```

Рядки не однакові: обсяг і число прогнозних спринтів різні. Збігаються дати,
бо перший сценарій включає два змодельовані спринти, а другий відлічує
ще чотири після них. Арифметика: 2026-11-13 + (6 − 1) × 14 = 2027-01-22;
2026-11-27 + 4 × 14 = 2027-01-22.

Яку дату я називаю замовнику вголос і чому саме її: у навчальному сценарії
робочий орієнтир P85 залишку, 2027-01-22, тобто не менше 85% прогонів

Це умовний результат моделі, який не підтверджує реальну ймовірність
завершення проєкту до цієї дати; після фактичного спринта 2 його треба замінити.

## 5. Чого вартий прогноз на моїх даних

Три прогони на навчальних даних курсу `lr09_reference_velocity.csv`, обсяг
фіксований умовою, 220 points. Четвертий рядок це ваш власний сценарій залишку
для порівняння.

| Джерело velocity | Спринтів в історії | P50 | P85 | Ширина інтервалу |
| --- | :-: | :-: | :-: | :-: |
| Навчальні дані, усі спринти | 12 | 12 | 14 | 2 |
| Навчальні дані, спринти 1 і 2 | 2 | 12 | 12 | 0 |
| Навчальні дані, спринти 5 і 6 | 2 | 16 | 18 | 2 |
| Мої спринти, навчальна модель залишку | 2 | 4 | 4 | 0 |

Навчальні velocity: [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9];
другий прогін використовує [21, 17], третій [23, 6]. Для кожного
навчального прогону обсяг однаковий 220 SP; власні 43 SP мають інший
обсяг, тому порівнюється форма розподілу, а не безпосередньо строк для 220 SP.

Що показує це порівняння: на спринтах 1–2 інтервал звужується з 2 до 0,
бо два близькі значення не містять повільних спринтів усієї історії.
На спринтах 5–6 ширина залишається 2, але весь інтервал зсувається
з 12–14 до 16–18: важливі і розкид відібраних значень, і їхній рівень.
Тому вузький інтервал власної моделі 4–4 означає лише обмеженість двома
припущеними спостереженнями та цілими спринтами, а не точність реального прогнозу.

Збіг P50 і P85 не отримано діленням на середню: обидва перцентилі взято
з 10 000 окремих прогонів. На дискретному розподілі вибірковий P50
може змінитися на один спринт при іншому seed, якщо накопичена ймовірність
лежить біля 50%; фіксований seed робить наведений результат відтворюваним,
але не додає даних і не підвищує достовірності моделі.

Точна перевірка дискретного розподілу підтвердила цей ефект: для навчальних
[23, 6] теоретичні P50/P85 становлять 15/18, тоді як виконані 10 000 прогонів
дали 16/18; ймовірність завершення до 15-го спринта дорівнює рівно 50%.
Аналогічно власна модель має теоретичні 5/6 для всього релізу та 3/4 для
залишку, а за наведеним seed отримано 6/6 і 4/4. У CSV збережені результати
фактично виконаного Monte Carlo; різниця на один спринт у медіані показує
похибку вибіркового перцентиля, а не іншу формулу чи округлення дати.
